# Truehand for Mac

A thin Tauri 2 shell around `truehand serve --app`: no domain logic.

- Starts the server as a daemon in its own session (closing the window or quitting the shell leaves agents running), or reuses the one it started before. Token and shell secret are generated by the shell, passed on stdin, and kept only in one Keychain item (service `it.spaghetticoders.truehand`, account `app`) together with the server's url and pid. Server log: `~/.truehand/app/serve.log`.
- The Keychain item's ACL lets only this Truehand.app read it without asking (decrypt bound to the app's cdhash, nobody may change the ACL). Anything else, an agent running `security find-generic-password -w` included, gets a visible macOS prompt instead of the secret.
- Before sending the token or the secret anywhere, the shell makes whoever listens on the server's address prove it knows the secret: `POST /api/shell/challenge {nonce}` must answer HMAC-SHA256(SHA-256(shell secret), "truehand-shell-challenge/1\n" + nonce). Nothing answers: a new server is started. Something else answers: nothing is sent and the window says the server is not recognized. Every request the shell makes repeats the check.
- Signs the web view in with `POST /api/login` from Rust and sets the `th_session` cookie natively: the token never reaches JavaScript.
- Once its approver key exists, the shell gives the server its public half (`POST /api/shell/key`, Bearer + shell secret) at every start or reuse and right after creating it: the server keeps it in memory to check intents forwarded to remote machines.
- Tray: Open, Open at Login, Quit (asks whether to stop the server too, with `POST /api/shutdown`; stopping it also deletes the Keychain item). Only if that fails does the shell send SIGTERM, and only to the pid the server announced, while its command and start time are the ones recorded then.

## JavaScript API (window.__TAURI__.core.invoke)

| command | returns | |
|---|---|---|
| `shell_request({ method, path, body })` | `{ status, body }` | adds `X-Truehand-Shell`; only the paths in `src-tauri/src/allow.rs` |
| | | for `POST …/commit-config`, and `POST /api/queued/{qid}/confirm` of a queued commit-config, the shell adds `thisMacKey` (this Mac's approver public key, if it exists) so the OS dialog labels each approver as this Mac's key or a foreign one |
| `pick_folder()` | `string \| null` | native folder dialog |
| `start()` | url | starts or reuses the server and signs the web view in again |
| `sign_intent({ projectId, taskId, action, approver })` | `{ intent, format: "es256", sig }` | Touch ID, Secure Enclave key; one at a time |
| `approver_key_fingerprint()` | `string \| null` | this Mac's key fingerprint; null if it has no key yet (never creates one, no Touch ID) |
| `approver_public_key()` | `{ pem, key }` | PEM for `approvers` in `.truehand/config.yaml`; `key` is the fingerprint the server shows next to each approver (first 12 hex of SHA-256 of the SPKI DER), to tell this Mac's key from another under the same name |

`sign_intent` asks the verified server for the intent (`POST …/tasks/{id}/intent`), checks it field by field with the rules of `internal/sign` `Intent.Check`, checks that the server's message is the same bytes it rebuilds, shows action, repo, task and title, branch and the abbreviated plan or commit sha in the Touch ID prompt, and signs those bytes with a P-256 key created in the Secure Enclave on first use (CryptoKit, `.privateKeyUsage` + `.biometryCurrentSet`: Touch ID for every signature, and a new fingerprint makes the key unusable, so register the new public key). The private key cannot leave the Secure Enclave; its wrapped form is in `~/Library/Application Support/it.spaghetticoders.truehand/approver-se.key` (0600) and is useless on another Mac.

## Build

Needs Go, bun, cargo and Xcode's Swift toolchain.

```sh
make app                # bin/truehand with the web app embedded (repo root)
cd shell
bun install --frozen-lockfile
bun run build           # copies ../bin/truehand as the sidecar, builds Truehand.app and the .dmg
cd src-tauri && cargo test
```

Output: `src-tauri/target/release/bundle/macos/Truehand.app` (about 20 MB, 5 MB of it the shell) and `bundle/dmg/`. Signed ad hoc only: each new build has a new cdhash, so the first launch after an update asks once to read its Keychain item (choose "Always Allow").

## Try it without touching the real server

```sh
open -n --env TRUEHAND_SHELL_HOME=/tmp/th-home --env TRUEHAND_SHELL_ADDR=127.0.0.1:7899 src-tauri/target/release/bundle/macos/Truehand.app
```

The server then runs with `HOME=/tmp/th-home` on that port, with its own Keychain account (`test:<home>`). These two variables are read by release builds too, on purpose, so the bundle that ships is the one tried. They only choose where a new server lives: whoever can set them when launching the app can already run `truehand serve` themselves, and the shell still sends nothing to a server that fails the challenge.
